# Goal: the legacy client does on 7.40 what 7.40 does

## Goal

`AdtClientLegacy` and the legacy executors answer, on a SAP_BASIS 7.40 SP04 system, what that
system actually does — for every member they hand out. A member whose endpoint 7.40 serves sends
the request 7.40 accepts; a member whose endpoint 7.40 does not serve is refused by the library
without a request. No member reports success for an answer that carries nothing.

The goal is not to replace every endpoint. It is to determine exactly which endpoints 7.40 serves
and to implement those; a member whose function 7.40 offers only through a different endpoint
family (where-used through RIS, package contents through `nodestructure`, object types through
`typestructure`) is refused here. Reading and changing what ADT does not offer on 7.40 is the work of
a separate legacy MCP server, which goes through local reports on the system, not through ADT.

## Measured on 7.40 SP04 (over RFC, and over HTTP where stated)

1. **Delete.** `DELETE <object>` without a lock handle answers 400 "Parameter lockHandle could not
   be found" for a class, a program, an interface and a function group. LOCK, then
   `DELETE <object>?lockHandle=`, then UNLOCK deletes a class, program, interface, function group,
   function module and DDL source. The class controller also reads `corrNr` from the URL.
2. **Deletion check.** `POST /sap/bc/adt/deletion/check` answers 404 over RFC and 200 with an empty
   body over HTTP: there is no deletion API.
3. **Transports.** `/sap/bc/cts/*` is unreachable over HTTP (ICF 404 before any logon). Over RFC
   `GET /sap/bc/cts/transportrequests` answers the user's list. Creating a request
   (`POST /sap/bc/cts/transportrequests`) answers 400 "user action is not supported".
4. **Empty 200s.** An unknown path under `/sap/bc/adt/*` answers 200 with an empty body over HTTP:
   transformations, scalar functions, append structures, DDIC sources (tables, domains),
   enhancements.
5. **Where-used.** `usageReferences` answers 404. 7.40 serves the RIS sequence
   `fullnamemapping` → `metadata?RIS_REQUEST_TYPE=OBJECT_TYPE` →
   `metadata?RIS_REQUEST_TYPE=WUL_TYPES_COMPLETE` → `whereused?RIS_REQUEST_TYPE=WHERE_USED_LAZY`.
6. **Virtual folders and object types.** `virtualfolders/contents` and `objecttypes` answer 404.
   `repository/nodestructure` (package contents, `parent_type=DEVC/K`) and
   `repository/typestructure` are served.
7. **Class run.** 7.40 has neither `IF_OO_ADT_CLASSRUN` nor `/oo/classrun`.
8. **Packages.** `GET /packages/{name}` answers 404 and `POST /packages` answers 405, over RFC and
   HTTP; the library refuses read and create, and still sends lock, check and deletion check.
9. **Unit tests.** `POST /sap/bc/adt/abapunit/testruns` with `<options>` answers the finished result
   for a class, a program, a function group and a function module; the library's legacy program,
   function group and function module runners refuse `run` and `runSync` without a request.
10. **Function includes.** Creating one as `application/vnd.sap.adt.functions.fincludes.v2+xml`
    answers 400 "No content handler found"; `application/vnd.sap.adt.functions.fincludes+xml`
    creates it.

## Invariants

- **Legacy differences live in the legacy classes only.** The legacy client extends the normal one
  and overrides only what differs; no legacy branch in the main handlers, the connection or the
  header pairs.
- **Only what was measured.** A legacy behaviour is claimed "on 7.40 SP04" and only after a run on a
  7.40 SP04 system; nothing is inferred for other releases.
- **A refusal sends nothing.** A member whose endpoint 7.40 does not serve answers the library's
  refusal without a request, never a request whose empty answer reads as success.
- **The consumer decides.** Answers stay readable through `options.analyse`; the library's default
  verdict is strict.
- **RFC writes, HTTP reads.** Writes on legacy are supported over RFC; over HTTP legacy is read-only.
- **No retries, no timeouts.** The delete with a lock is the delete, not a fallback after a failed
  one.
