# The legacy package and its live cycles — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the `*Legacy` classes, their tests, the 7.40 ABAP test
environment and their docs into `@mcp-abap-adt/adt-clients-legacy`
(`packages/adt-clients-legacy`), apply the B4-measured class changes, and
prove every handler 7.40 serves with one live cycle per type.

**Architecture:** The order of the work:
1. The shared test harness becomes free of legacy, behind two seams.
2. The measured changes land on the legacy classes where they are.
3. The package skeleton is created.
4. The compiler drives the move: what the legacy classes need from the root
   is exported, and legacy leaves the root.
5. The live cycles are written in the package and run on E77.
6. The docs and versions follow.

**Tech Stack:**
- TypeScript;
- Jest (root and nested package configs);
- Biome;
- RFC through `@mcp-abap-adt/connection` / `sap-rfc-lite`;
- ABAP 7.40 SP04 (test environment only).

**Spec:** `docs/superpowers/specs/2026-10-26-legacy-package-design.md`.
**Goal doc:** `docs/superpowers/2026-10-26-legacy-package-goal.md`.
**Measurements:** the B2, B3, B4 and class-metadata-accept records in
`~/prj/e77-probe/e77-results/`.

## Global Constraints

- Legacy logic lives only in `*Legacy` classes (`extends` + `override`). The
  root package has no legacy at all once the move is done.
- The system type is declared by the consumer, never detected: no factory
  chooses a legacy class.
- Legacy is RFC-only.
- **Dependencies:**
  - only from the registry;
  - the legacy package depends on `@mcp-abap-adt/adt-clients` `^37.4.0`;
  - inside the repository the siblings may link while developing;
  - lockfiles are regenerated by npm only.
- npm scripts only: never `npx` or `node_modules/.bin` directly, never
  `--no-verify`.
- Commits end with the attribution lines. Work only in
  `.worktrees/legacy-package`, branch `feat/legacy-package`, PR #281.
- **Live runs:**
  - check the realm `[E77/182]` without logon before each;
  - `MCP_ENV_PATH=~/.config/mcp-abap-adt/sessions/e77-run.env`,
    `MCP_TEST_OVERLAY` = the E77 overlay;
  - the test user only;
  - any credential refusal stops everything;
  - never release a transport;
  - never touch an object the run did not create;
  - delete everything created, also on failure.
- A request's headers are the caller's: the library passes them through.
  The measured pairs are passed by the tests, as a consumer would.
- **Claims and coverage:**
  - every claim says "measured on 7.40 SP04", with its record;
  - a step not yet measured is measured before a test fixes it.
- **Tests:**
  - every new test is load-bearing (red before, or a guard proved by a
    temporary break);
  - a removed check takes its test with it.
- CLAUDE.md changes only with text the owner approved (Task 7).
- The test environment (`ZCL_LG7_ENV*`) is a utility. Findings there are
  recorded as debt unless they can touch another user's objects or data.

## Review Focus

1. **A cycle that fails midway.** The objects it created are still deleted,
   and a lock it took is released. Each cycle test has a `finally`, proved by
   failing one step on purpose (Task 5).
2. **A composite operation (message create, update or delete).** It is
   asserted as its full ordered sequence, every lock and unlock included
   (Task 5).
3. **The root package after the move.** It builds, its tests pass, and no
   legacy name is left in it. Asserted by the root AST rule (Task 4).
4. **A consumer installing only the legacy package from the registry.** It
   resolves `@mcp-abap-adt/adt-clients` `^37.4.0` and imports
   `AdtClientLegacy` (Task 7, after publishing).
5. **An empty `200` from 7.40.** A message class that does not exist reads
   `200` empty. The cycle asserts the measured answer, not a 404 (Task 5).

- [ ] Step 1: Copy adt-strategies' package wiring, read whole: its
  package.json, configs and how the root and the CI call it. Note what
  differs here: adt-strategies does not depend on the root package, and this

- [ ] Step 2: Resolve the not-yet-published root during development and in
  CI, with no link of any kind in any manifest:
  - **`package.json`.** It declares `@mcp-abap-adt/adt-clients` `^37.4.0`
    and nothing else for it. No `file:`, `link:` or `workspace:`.
  - **Type check.** The package's `tsconfig` maps `@mcp-abap-adt/adt-clients`
    (and its subpaths) to the root's `src` through `paths`.
  - **Tests.** Jest maps it the same way through `moduleNameMapper`.
  - **Build.** The build emits `import … from '@mcp-abap-adt/adt-clients'`
    unchanged, because `paths` does not rewrite imports, so the published JS
    resolves from the registry.

    adt-clients 37.4.0 on the registry. Add it to the package's lockfile only
    after 37.4.0 is published, in Task 7, through npm.

    unit-tests the package.

    lockfile is regenerated by npm against the registry. Then check the
    package for `"link": true` and for anything not resolved from the
    registry.
- [ ] Step 2b: Give the package two Jest configurations:

    timeout. This is what CI runs.

    and `admin/legacy-env/**`, runs sequentially (`--runInBand`), uses the
    root harness's `globalSetup`/`globalTeardown` by relative path, sets the
