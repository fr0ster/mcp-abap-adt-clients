## What is known (measured, not read off code)

From mcp-abap-adt (BASIS 816 on-prem + ABAP Cloud trial, 2026-10-02/09-25):

| type | ADT | what works |
|---|---|---|
| `ENHS/XSB` BAdI spot | served | `GET enhsxsb/{spot}`, Accept `…enhancements.v1+xml` |
| `ENHS/XS` plain spot | **not served** — `500 I::000`, Eclipse opens SAP GUI | — |
| `ENHO/XHH` source code plugin | served | `GET enhoxhh/{name}/source/main` |
| `ENHO/XHB` BAdI impl | metadata only | `enhoxhb/{name}`; no `/source/main` |
| `ENHO/XH` class enhancement | **not served** — `500`, Eclipse opens SAP GUI | — |

- A subtype is found by `repository/informationsystem/search?operation=quickSearch&objectType=ENHO|ENHS`;
  the subtype filter is ignored, the subtype is each hit's `adtcore:type`.

Measured today (2026-10-15, E19 tunnel + trial):

- Discovery on both: collections `enhoxh`, `enhoxhb`, `enhoxhh`, `enhsxs`,
  `enhsxsb` (+ `/validation` each), `enhsxsb/search`; a `source` template only
  for `enhoxhh`. **`…/source/main/enhancements/elements` is not in discovery.**
- That endpoint is nevertheless served: content type
  `application/vnd.sap.adt.enhancements.v3+xml`. A class with no enhancements
  answers 200 `<enh:enhancements/>` on both systems; `SAPMV45A` (E19) answers
  `enh:enhancementImplementations` of type `ENHO/XHH`, each with
  `sourceCodePlugin` (`enh:uri` → `enhoxhh/<name>/source/main`, base64
  `enh:source`, `full_name` `\PR:…\EX:…\EI`, position in the host). So #227 is
  ENHO seen from the host side, not something unrelated to it.
- A nonexistent class answers **400** `EnhancementError`, T100 `SEEF_BASE/104` —
  not 404.

What adt-clients has today (`src/core/enhancement/`, 1645 lines):

- Full CRUD + lock/check/activate/versions for **all five** subtypes,
  including the two ADT does not serve.
- `create.ts` builds a body its own comment calls "a template that should be
  verified against SAP documentation" — namespace
  `http://www.sap.com/adt/enhancements`, root `enh:enhancement`; what SAP
  answers with is `enhs:objectData` in `…/enhancements/enhs`. Never verified.
- **No integration test** for the family (`src/__tests__/integration/core/` has
  no `enhancement/`); only unit tests on address encoding and Accept.

## Global Constraints

- One member = one ADT request; no `analyse ??`; SAP failures through the
  strategy, never a throw or a rewrap; a member throws only for a cause inside
  the library.
- Addresses only in `src/endpoints/objects.ts`.
- Only `lock`/`unlock` touch the session type.
- Dependencies from npm only; interfaces published before adt-clients uses it.
- `ILogger`, never `console.*`.
- One SAP-touching run at a time, `npm run test:detached`, no `src/` edits while
  a run is in flight. Test objects are created under `default_package`
  (trial `ZADT_BLD_PKG03`; E19 `ZAC_TEST_PKG` on `E19K907111`, from `~/.config/mcp-abap-adt/test-config.e19.yaml`), the target named before creating. Trial logins: ask first.
- Versions and CHANGELOG version: the user's.

## Review Focus

1. A subtype ADT does not serve — the caller gets SAP's answer, not a library
