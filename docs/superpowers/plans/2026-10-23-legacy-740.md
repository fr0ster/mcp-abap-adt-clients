# The legacy client on 7.40 SP04 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to carry this plan out task by task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `AdtClientLegacy` and `AdtExecutorLegacy` answer, on SAP_BASIS 7.40 SP04 over RFC, what
that system does for every member they hand out: a served member sends the measured request, an
unserved one answers the library's refusal without a request, and no member reads an empty answer
as success.

**Architecture:** every difference lives in a legacy class — a `*Legacy` subclass that overrides
only the members that differ, `absentOnLegacy` for a type 7.40 lacks, and the two legacy clients'
getters that hand them out. Main handlers, `src/core/shared/*` functions the modern handlers call,
the connection and the header pairs stay as they are. A unit inventory test walks every handler's
prototype chain and holds each public member to exactly one decision of the spec.

**Tech stack:** TypeScript (strict, CommonJS), Jest 30 with ts-jest, Biome, the TypeScript parser
for source tests, `@mcp-abap-adt/connection` (dev only) over RFC for the live checks.

**Spec (binding):** `docs/superpowers/specs/2026-10-23-legacy-740-design.md`. Goal:
`docs/superpowers/2026-10-23-legacy-740-goal.md`. Section numbers below (§n) are the spec's.

## Global Constraints

- **One wire: RFC.** Legacy is supported and measured over RFC only; nothing in the library detects or branches on the wire — no wire option, no HTTP guard (§3).
- **Basis of every claim: SAP_BASIS 7.40 SP04**, from an RFC probe record; nothing is inferred for another release (goal, §1).
- **One refusal shape:** answered through `failed()`, never thrown — `origin: 'refusal'`, `code: AdtObjectErrorCodes.UNSUPPORTED_OPERATION`, a message naming the operation, the endpoint 7.40 lacks, and what to use instead where there is one; zero requests; no new error code (§2.1).
- **No legacy branch outside the legacy classes** (`*Legacy` subclasses, `absentOnLegacy`, `AdtClientLegacy`, `AdtExecutorLegacy`; the factories `createAdtClient`/`createAdtExecutor` choose by `isModernAdtSystem` as today) (§2.2).
- **Version 37.3.0, a minor:** no public type change — constructors stay, getters return subclasses assignable to the old types, `AdtPackageLegacy.read` stays (refused); no new root export; no dependency moves (§15).
- **No retries, no timeouts of the library's choosing:** the delete with a lock is the delete, not a fallback; the caller's `options.timeout` is the caller's (§4.2, §13).
- **Registry-only dependencies:** no `file:`/`link:` specifier, no `"link": true` in `package-lock.json`; `npm install --package-lock-only` after the version change.
- **npm scripts only:** never `npx`; scripts call installed bins. Single unit tests run as `npm run test:unit -- -t '<describe title>'`; the whole unit suite as CI runs it, `MCP_ENV_PATH=/tmp/nonexistent-env npm run test:unit`.
- **One PR (#271), branch `feat/legacy-740`:** each task below is one or more commits on it; no other PR.
- **No identities in the tree:** no host names, SAP system ids, user names, request numbers or lock handles in code, tests, scripts, docs or commits.
- **Live runs need the owner's go-ahead:** a run against a SAP system (Tasks 15–16) starts only after the owner confirms the target and that the profile is up.

## Review Focus

1. **The inventory sees every public member.** Inherited members (`AdtClassMemberBase`'s six,
   `AbapUnitRunner`'s `getStatus`/`getResult`), accessors (`pendingLocks`), symbol-keyed members
   (`[Symbol.asyncDispose]`), the plain objects `absentOnLegacy` builds, and runtime-visible
   TypeScript-private/protected methods (`AdtUtilsLegacy.refuse`, `AbapUnitRunner.startByObject`,
   `startSync`) that must be excluded by a checked list, not by a guess. Pinned in Task 1 by
   `legacyMemberInventory.test.ts` ("every public member is decided exactly once").
2. **The runner body is the modern `runSync` body, byte for byte.** `<options>` is sent even when the
   caller gives no options; a caller's `scope` reaches the body; `run` is read by the `run` strategy
   and `runSync` by `result`; the function module's `run` refuses. Pinned in Task 3 by
   `classTestRunner.test.ts`, `programTestRunner.test.ts`, `functionTestRunners.test.ts`,
   `syncTestRunners.test.ts`.
3. **The delete URL.** Exactly one `DELETE <object URI>?lockHandle=<h>`, the handle URL-encoded,
   `&corrNr=<transport>` only when `transportRequest` is given (trimmed), no `lockHandle` parameter
   and still one request when no handle is given, no `LOCK`/`UNLOCK`, no `setSessionType`. Pinned in
   Task 2 by `legacyDeleteTimeout.test.ts`.
4. **Type refusals in `readObjectMetadata`/`readObjectSource` match every alias, in any case**
   (`domain`/`doma/dd`, `dataelement`/`dtel`/`dtel/de`, `structure`/`stru/dt`, `table`/`tabl/dt`,
   `tabletype`/`ttyp/df`, `package`/`devc/k`), while an unknown type is still thrown as today. Pinned
   in Task 7 by `legacyUtils.test.ts`.
5. **The integration header helper after the class `update` override goes and
   `AdtFunctionIncludeLegacy` arrives.** A legacy class `update` resolves to the client's provider
   pair (`text/plain` on a non-unicode `AdtContentTypesBase`), the legacy function include `create`
   gets `application/vnd.sap.adt.functions.fincludes+xml` both ways, and the modern client keeps
   v2. Pinned in Tasks 2 and 4 by `integrationHeadersOf.test.ts`.
