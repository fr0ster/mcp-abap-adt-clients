# ATC probe evidence — E19 on-premise, 2026-08-28

Captured by `scripts/probe-atc.ts` against package `TEST_MCP`, **twice: once over HTTP and
once over RFC**, because a fact about an endpoint has to survive both wires to be a fact
about the endpoint. Raw captures stay out of git (`atc-e19*/` is ignored) — these are the
responses the reports quote.

System: `RFCSAPRL 816`, kernel `916`, client 100. The nominated check variant is
`Z_ATC_TEST`; a second full run used `--variant=ABAP_CLOUD_DEVELOPMENT_DEFAULT`.

**Headline: no object type could be confirmed, and not for any reason to do with the
client.** Every check run on this system aborts. The three facts in the second half were
still settled, because they live in traffic that does not depend on the checks running.

## Recorded, and still inconclusive

- **`includeExemptedFindings`** — the same finished worklist read `false` then `true` returned
  byte-identical bodies. Read against an aborted run, so this says nothing about the flag.
- **`withLongPolling=true`** on a run in flight — `123 ms` (HTTP) / `110 ms` (RFC) against a
  plain read started at the same moment at `212 ms` / `219 ms`, both `running`. Not a
  difference anything can be concluded from.

## Transport parity

Every step, both manifests:

| step | HTTP | RFC |
|---|---|---|
| `run-class-oo-classes` | 201, `Location` present | 201, `Location` present |
| `customizing-POST` | 405 | 405 |
| `findings-checkstyle` | 406 | 406 |
| `run-maximumVerdicts-0` | 400 | 400 |
| `run-status-by-worklist-id` | 404 | 404 |
| verdict | `INCOMPLETE — 0 of 9` | `INCOMPLETE — 0 of 9` |

The RFC wire surfaces only the headers ADT set (`~server_protocol`, `content-type`, and
`location` where there is one); HTTP additionally carries the ICM's `sap-*` headers. Nothing
the contract depends on is lost.
